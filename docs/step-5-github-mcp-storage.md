## Сохранение прогонов через GitHub MCP

Чтобы отслеживать динамику цен, каждый прогон нужно где-то хранить. Держим прогоны в отдельном приватном репозитории `tracker-data` — так данные не смешиваются с кодом скиллов, а история прогонов живет своей жизнью.

Писать туда `tracker` будет через GitHub MCP: Claude Code обращается к GitHub напрямую через MCP и коммитит файл в репозиторий `tracker-data`, не клонируя его локально. На этом шаге вы заодно знакомитесь с тем, как ассистент работает с внешними сервисами через MCP.

## Задачи

1. Проверьте, что все готово с прошлых шагов: приватный репозиторий `tracker-data` заведен, команда `/mcp` показывает сервер `github` как connected, а токен видит этот репозиторий и имеет права Contents: Read and write. Если что-то из этого не сходится — вернитесь к шагу «Постановка и репозиторий», там разобран порядок подключения и что делать при ошибке 403.
2. Договоритесь о схеме хранения: один прогон — один файл `YYYY-MM-DD.json` (имя — дата прогона) в корне `tracker-data`, внутри — таблица прогона из прошлого шага в формате JSON.
3. Дополните скилл `tracker`: после сборки таблицы он через GitHub MCP коммитит ее как `YYYY-MM-DD.json` в репозиторий `tracker-data`. Запись файла через MCP — это сразу отдельный коммит, без локального `git clone` и `git push`.
4. Запустите трекер и убедитесь, что в `tracker-data` появился файл за сегодняшнюю дату с корректным содержимым, а коммит виден в истории репозитория на GitHub.

## Результат шага

Прогоны `tracker` хранятся в отдельном приватном репозитории `tracker-data`: каждый прогон — отдельный файл `YYYY-MM-DD.json`, закоммиченный через GitHub MCP, отдельно от кода скиллов. История прогонов накапливается по датам прямо в этом репозитории.
