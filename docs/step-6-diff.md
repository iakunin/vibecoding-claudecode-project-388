# Проект: Трекер цен с Claude — Шаг 6

Источник: https://ru.hexlet.io/projects/388/members/53773?step=6

## Сравнение с прошлым прогоном

Накопленная история позволяет показывать не сырые цены, а изменения. На этом шаге `tracker` учится сравнивать текущий прогон с предыдущим.

`tracker` через GitHub MCP читает последний сохраненный файл из репозитория `tracker-data`, считает diff между ним и свежим прогоном и применяет правила значимости изменений из `KNOWLEDGE.md` (например, какой порог изменения цены считать существенным, как трактовать появление/исчезновение скидки или рассрочки).

## Задачи

1. Дополните `tracker`: перед сохранением нового прогона он через GitHub MCP получает список файлов в репозитории `tracker-data` и читает последний по дате — это предыдущий прогон. Если прошлых прогонов еще нет — это первый запуск, сравнивать не с чем.
2. Опишите расчет diff: сопоставить товары по URL и для каждого сравнить поля `regular_price`, `sale_price`, `has_credit` между прошлым и текущим прогоном. На выходе — список изменений по каждому товару.
3. Создайте файл `KNOWLEDGE.md` и опишите в нем правила значимости: какой порог изменения цены считать существенным (например, ±1%), как трактовать появление или исчезновение скидки, изменение рассрочки, появление нового или пропажу старого товара.
4. Научите `tracker` применять эти правила к diff и отбрасывать незначимые изменения (например, колебание цены на копейки). Так на выходе остается только то, о чем стоит уведомлять.
5. Проверьте на двух прогонах подряд (можно вручную поправить пару цен в прошлом файле в репозитории `tracker-data`): убедитесь, что трекер показывает именно значимые изменения, а не весь список цен.

## Результат шага

`tracker` сравнивает свежий прогон с предыдущим из репозитория `tracker-data`, применяет правила значимости из `KNOWLEDGE.md` и выдает список только значимых изменений цен, а не сырые цены целиком.
