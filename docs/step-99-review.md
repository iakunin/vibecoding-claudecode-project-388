# Проект: Трекер цен с Claude — Проверка

Источник: https://ru.hexlet.io/projects/388/members/53773/reviews

## Как мы проверяем проект

Формально проект проходит простую (smoke) проверку: тест-харнесс в контейнере убеждается, что в репозитории есть ключевые файлы инструмента — скиллы `extract-price` и `tracker`, файл правил `KNOWLEDGE.md`, helper `send.py` и `README.md`. Логика трекера живёт в Claude-скиллах, поэтому глубокой автоматической проверки кода нет.

Главный целевой критерий: инструмент собран в подходе вайбкодинга — в идеале весь код и скиллы написаны с помощью агента, а трекер реально проходит полный цикл: цены → сохранение прогона → сравнение → Telegram.

Статус проверки можно посмотреть в репозитории GitHub. Вывод проверки находится во вкладке Actions в workflow `hexlet-check`.

## Порядок проверки

Проверка идёт по пунктам, указанным ниже. Если на верхнем уровне есть серьёзные проблемы, то проверка останавливается до исправления: пока вы правите верхний уровень, код под ним всё равно меняется, поэтому проверять сразу всё смысла нет.

1. Секреты (токен бота, chat id и токен GitHub только в `.env` или Secrets — ни в файлах, ни в истории коммитов)
2. Полный цикл проверен вживую (два прогона подряд, свежий сохранён в `tracker-data`, в Telegram пришла сводка значимых изменений)
3. Контракт извлечения цены (`extract-price` отдаёт объект, а не текст, и `null` при ошибке)
4. Раскладка проекта (скиллы в `.claude/skills/` с заполненными `name` и `description`, `KNOWLEDGE.md` с правилами значимости, `send.py` на стандартной библиотеке)
5. Данные и личное отдельно (прогоны в приватном `tracker-data`, chat id и личные ссылки в репозитории не оставлены)

## Что должно работать

В проекте должен корректно отрабатывать полный цикл трекера:

- **Извлечение цены:** скилл `extract-price` по одному URL возвращает объект контракта `{ regular_price, sale_price, has_credit }` (а не текст в свободной форме), нормализует число и отдаёт `null` при ошибке.
- **Сбор таблицы:** скилл `tracker` за один запуск обходит весь зашитый список URL, вызывает `extract-price` для каждого и собирает единую таблицу прогона.
- **Сохранение прогонов:** свежий прогон сохраняется в отдельный приватный репозиторий `tracker-data` как файл `YYYY-MM-DD.json` через GitHub MCP.
- **Сравнение с прошлым:** `tracker` читает предыдущий прогон из `tracker-data`, считает diff и оставляет только значимые изменения по правилам из `KNOWLEDGE.md`.
- **Доставка в Telegram:** значимые изменения приходят отдельным сообщением; если изменений нет — корректное «Значимых изменений цен нет».

## Требования к оформлению

Ожидаемая структура репозитория проекта:

```
.claude/skills/
├── extract-price/SKILL.md   # один URL → { regular_price, sale_price, has_credit }
└── tracker/SKILL.md         # обход списка URL, таблица, хранение, diff, Telegram
.claude/agents/
└── tg-summary.md            # оформление TG-сводки на Haiku (опционально)
KNOWLEDGE.md                 # правила значимости изменений цен
send.py                      # отправка сообщения в Telegram (urllib)
.env                         # токен и chat id — в .gitignore
```

Отдельный приватный репозиторий (история прогонов):

```
tracker-data/
└── YYYY-MM-DD.json          # один прогон в день
```

- Скиллы лежат в `.claude/skills/`, у каждого заполнены поля `name` и `description`.
- Есть файл `KNOWLEDGE.md` с правилами значимости изменений (порог цены, появление/исчезновение скидки, изменение рассрочки, состав списка).
- Есть helper `send.py` — только стандартная библиотека Python, без внешних зависимостей; токен и chat id берутся из переменных окружения или из `.env`.
- Прогоны хранятся в отдельном приватном репозитории `tracker-data`, а не в репозитории со скиллами.
- Опционально: сабагент `tg-summary` на дешёвой модели Haiku для оформления текста сводки.

## Что проверить самому

Автопроверка тривиальная, поэтому перед сдачей пройдитесь по проекту сами:

1. **Нет секретов в репозитории.** Токен бота (`TELEGRAM_BOT_TOKEN`) и chat id (`TELEGRAM_CHAT_ID`) лежат только в `.env` (он добавлен в `.gitignore`) или в Secrets окружения — и нигде не зашиты в `SKILL.md`, `send.py` или `README.md`. Проверьте историю коммитов: токен не должен был попадать в репозиторий ни разу. Если попал — отзовите его в @BotFather командой `/revoke` и заведите новый.
2. **Токен GitHub тоже секрет.** Если MCP подключён по личному токену, сам токен не должен лежать в репозитории: в `.mcp.json` стоит подстановка вида `${GITHUB_MCP_PAT}`, а значение задано в переменных окружения. Проверьте историю коммитов и там тоже. Если токен засветился — отзовите его на github.com/settings/personal-access-tokens и выпустите новый.
3. **Данные прогонов — отдельно.** Файлы `YYYY-MM-DD.json` с ценами лежат в приватном `tracker-data`, а не в основном репозитории со скиллами.
4. **Личное не светится.** Chat id, личные ссылки и аккаунты не оставлены в скиллах и `README.md`.
5. **Контракт цены соблюдён.** На реальных страницах `extract-price` возвращает именно объект `{ regular_price, sale_price, has_credit }`.
6. **Полный цикл проверен вживую** хотя бы дважды (чтобы появился diff): прогон сохранился в `tracker-data`, а в Telegram пришла сводка значимых изменений.

## Что дальше

После того как трекер заработал, его можно развивать как продукт.

- **Больше ниш и списков:** несколько наборов товаров и отдельные `tracker`-скиллы под разные категории.
- **Запуск по расписанию:** автоматический прогон по графику (cron / Routines), чтобы сводки приходили без ручного запуска.
- **Другие каналы доставки:** кроме Telegram — email, Slack, push-уведомления.
- **Аналитика динамики:** графики изменения цен по накопленной истории прогонов в `tracker-data`.
- **Умные правила:** пороги под конкретный товар, «цель по цене» и оповещение при её достижении.
