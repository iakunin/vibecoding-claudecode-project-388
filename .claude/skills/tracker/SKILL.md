# tracker

Один запуск = один прогон по всему списку отслеживаемых товаров.

Зачем: подгадать выгодный момент покупки. Смотреть цены имеет смысл целиком по списку, а не по одному товару — так видно, какая позиция просела относительно соседних.

## Контракт

**Вход:** ничего. Список зашит в этом файле, перечислять ссылки при запуске не нужно.

**Выход:** одна markdown-таблица — строка на товар, все товары из списка, в том же порядке.

**Побочный эффект:** прогон сохраняется в репозиторий `tracker-data` как `YYYY-MM-DD.json`.

## Алгоритм

### 1. Пройти по списку

Для **каждого** URL из таблицы вызови скилл `extract-price` — он принимает ровно один URL и возвращает объект `{regular_price, sale_price, has_credit}`.

`tracker` **не содержит собственной логики извлечения цены**: не ходит curl'ом за страницей сам, не парсит HTML, не знает про `span.price` и ловушку `itemprop="price"`. Всё это живёт в `extract-price`. Если парсинг сломался — чинить надо `extract-price`, а не этот файл.

Товары независимы — вызовы можно делать параллельно.

Пропускать URL нельзя: в таблице должны оказаться все строки списка, включая те, где цену получить не удалось.

### 2. Собрать таблицу прогона

Одна строка на товар, поля — ровно те, что вернул `extract-price`:

```markdown
| Товар | URL | regular_price | sale_price | has_credit |
|---|---|---|---|---|
| ADAM A4V (чёрный) | https://united-music.ru/ru/adam-a4v.html | 48600 | — | да |
| ADAM A4V (белый) | https://united-music.ru/ru/adam-a4v-white.html | 50100 | — | да |
```

Оформление ячеек:

- `regular_price` / `sale_price` — целое число рублей как есть, без пробелов-разделителей и без `р.`.
- `sale_price: null` → `—` (скидки нет).
- `has_credit` → `да` / `нет`.
- Любое поле `null` из-за ошибки → `—`.

Порядок строк — как в списке выше. Не сортируй по цене: строки должны совпадать со списком, чтобы прогоны можно было сравнивать между собой.

Это будущая запись прогона: на следующих шагах она же ляжет в хранилище и пойдёт в diff.

### 3. Сохранить прогон в tracker-data

История прогонов живёт отдельно от кода скиллов — в приватном репозитории `iakunin/tracker-data`, ветка `main`.

Схема хранения: **один прогон — один файл `YYYY-MM-DD.json` в корне репозитория**. Имя файла — дата прогона по местному времени, `date +%F`.

Содержимое — та же таблица прогона, только в JSON:

```json
{
  "date": "2026-09-20",
  "items": [
    {
      "name": "ADAM A4V (чёрный)",
      "url": "https://united-music.ru/ru/adam-a4v.html",
      "regular_price": 48600,
      "sale_price": null,
      "has_credit": true
    }
  ]
}
```

- `items` — все товары списка, в том же порядке, что и в таблице. Не выкидывай товар, по которому цену получить не удалось: у него просто `null` в ценах.
- Значения — как их вернул `extract-price`: целые числа и `null`, без оформления (`—` и `да`/`нет` живут только в markdown-таблице).

Запись идёт через GitHub Contents API одним коммитом, без `git clone` и `git push`:

```bash
DATE=$(date +%F)
RUN="$TMPDIR/$DATE.json"   # сюда положен JSON прогона
TOKEN=$(gh auth token)
API="https://api.github.com/repos/iakunin/tracker-data/contents/$DATE.json"

CONTENT=$(base64 < "$RUN" | tr -d '\n')
SHA=$(curl -sS -H "Authorization: Bearer $TOKEN" "$API" \
  | python3 -c 'import sys,json; print(json.load(sys.stdin).get("sha",""))')

if [ -n "$SHA" ]; then
  BODY="{\"message\":\"Run $DATE\",\"content\":\"$CONTENT\",\"sha\":\"$SHA\"}"
else
  BODY="{\"message\":\"Run $DATE\",\"content\":\"$CONTENT\"}"
fi

curl -sS -X PUT -H "Authorization: Bearer $TOKEN" -H "Accept: application/vnd.github+json" \
  "$API" -d "$BODY"
```

Три грабли, каждая проверена на этом окружении:

1. **Файл и запись — в одном вызове shell.** `$TMPDIR` у песочницы и у команд вне её разный. Если записать JSON одной командой, а `base64` вызвать другой, прочитается пустота и в репозиторий уедет файл нулевого размера — причём GitHub ответит успехом.
2. **`gh api --method PUT` здесь падает** с `tls: failed to verify certificate: x509: OSStatus -26276`, хотя `gh api` на чтение работает. Отсюда `curl` с токеном из `gh auth token`. Токен в вывод не печатать.
3. **`${SHA:+-f sha=...}` в zsh не разворачивается в отдельные аргументы** — `sha` молча не доедет, и придёт `422`. Отсюда явный `if`.

`sha` нужен, только если файл за сегодня уже есть — при повторном прогоне в тот же день. Без него GitHub ответит `422`, с ним прогон перезапишется новым коммитом.

Почему не GitHub MCP, хотя задание шага про него: сервер `github` в `/mcp` не подключён, fine-grained токена нет. Задание шага 2 прямо разрешает этот запасной путь — «сохраняйте прогоны обычным git с тем же токеном». Схема хранения от этого не меняется: файл `YYYY-MM-DD.json` в корне `tracker-data`, один прогон — один коммит, без локального клона. Появится MCP — меняется только этот блок команд.

Прогон за прошлую дату задним числом не пиши: имя файла — всегда сегодняшняя дата.

После записи убедись, что ответ содержит `commit.sha`, и покажи ссылку на коммит под таблицей.

### 4. Отчитаться об ошибках

Если по какому-то товару `extract-price` вернул `null` — строка всё равно остаётся в таблице с прочерками, а под таблицей отдельным списком перечисли причины:

```
Не удалось получить цену:
- ADAM A77H — HTTP 404, страница не найдена
```

Не выдумывай цену, не подставляй значение соседнего товара и не бери число из прошлого прогона.

Если не удалось получить вообще ничего — всё равно выведи таблицу с прочерками и список причин. Пустой ответ — не результат.

Прогон с частично пустыми ценами всё равно сохраняется в `tracker-data`: пропуск в истории хуже, чем запись с `null`.

Если упала сама запись в репозиторий (нет сети, `gh` не авторизован, `403`) — скажи об этом прямо и покажи собранный JSON в ответе, чтобы прогон не потерялся. Не делай вид, что сохранение прошло.

## Частые ошибки

| Ошибка | Что делать |
|---|---|
| Обошёл один-два URL и отчитался | Прогон = весь список за один запуск |
| Спросил у пользователя, какие ссылки проверять | Список зашит здесь, спрашивать нечего |
| Начал парсить HTML сам | Вызывай `extract-price`, логика цены живёт там |
| Выкинул из таблицы товар, у которого не нашлась цена | Строка остаётся, в полях `—`, причина под таблицей |
| Отсортировал таблицу по цене | Порядок = порядок списка, иначе прогоны не сравнить |
| Вывел семь отдельных JSON-объектов | Результат прогона — одна таблица |
| Склонировал `tracker-data` локально | Запись идёт через GitHub API, коммит создаётся на стороне GitHub |
| Положил `—` и `да` в JSON | Оформление — только для markdown-таблицы, в файле числа и `null`/`true` |
| Получил `422` при повторном прогоне за день | Файл уже есть: передай его `sha`, чтобы перезаписать |
| Показал таблицу, умолчав про упавшую запись | Провал сохранения озвучивается явно |
