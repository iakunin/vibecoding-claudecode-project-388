# tracker

Один запуск = один прогон по всему списку отслеживаемых товаров.

Зачем: подгадать выгодный момент покупки. Смотреть цены имеет смысл целиком по списку, а не по одному товару — так видно, какая позиция просела относительно соседних.

## Контракт

**Вход:** ничего. Список зашит в этом файле, перечислять ссылки при запуске не нужно.

**Выход:** одна markdown-таблица — строка на товар, все товары из списка, в том же порядке.

Это единственное место, где список хранится. Добавить или убрать товар — отредактировать таблицу выше, больше ничего менять не нужно.

## Алгоритм

### 1. Пройти по списку

Для **каждого** URL из таблицы вызови скилл `extract-price` — он принимает ровно один URL и возвращает объект `{regular_price, sale_price, has_credit}`.

`tracker` **не содержит собственной логики извлечения цены**: не ходит curl'ом за страницей сам, не парсит HTML, не знает про `span.price` и ловушку `itemprop="price"`. Всё это живёт в `extract-price`. Если парсинг сломался — чинить надо `extract-price`, а не этот файл.

Товары независимы — вызовы можно делать параллельно.

Пропускать URL нельзя: в таблице должны оказаться все строки списка, включая те, где цену получить не удалось.

### 2. Собрать таблицу прогона

Одна строка на товар, поля — ровно те, что вернул `extract-price`:

```markdown
| Товар | URL | regular_price | sale_price | has_credit |
|---|---|---|---|---|
| ADAM A4V (чёрный) | https://united-music.ru/ru/adam-a4v.html | 48600 | — | да |
| ADAM A4V (белый) | https://united-music.ru/ru/adam-a4v-white.html | 50100 | — | да |
```

Оформление ячеек:

- `regular_price` / `sale_price` — целое число рублей как есть, без пробелов-разделителей и без `р.`.
- `sale_price: null` → `—` (скидки нет).
- `has_credit` → `да` / `нет`.
- Любое поле `null` из-за ошибки → `—`.

Порядок строк — как в списке выше. Не сортируй по цене: строки должны совпадать со списком, чтобы прогоны можно было сравнивать между собой.

Это будущая запись прогона: на следующих шагах она же ляжет в хранилище и пойдёт в diff.

### 3. Отчитаться об ошибках

Если по какому-то товару `extract-price` вернул `null` — строка всё равно остаётся в таблице с прочерками, а под таблицей отдельным списком перечисли причины:

```
Не удалось получить цену:
- ADAM A77H — HTTP 404, страница не найдена
```

Не выдумывай цену, не подставляй значение соседнего товара и не бери число из прошлого прогона.

Если не удалось получить вообще ничего — всё равно выведи таблицу с прочерками и список причин. Пустой ответ — не результат.

## Частые ошибки

| Ошибка | Что делать |
|---|---|
| Обошёл один-два URL и отчитался | Прогон = весь список за один запуск |
| Спросил у пользователя, какие ссылки проверять | Список зашит здесь, спрашивать нечего |
| Начал парсить HTML сам | Вызывай `extract-price`, логика цены живёт там |
| Выкинул из таблицы товар, у которого не нашлась цена | Строка остаётся, в полях `—`, причина под таблицей |
| Отсортировал таблицу по цене | Порядок = порядок списка, иначе прогоны не сравнить |
| Вывел семь отдельных JSON-объектов | Результат прогона — одна таблица |
